## Công việc đã làm

### Tài liệu và thiết kế

- Đã có bản đối chiếu yêu cầu SRS với Flutter prototype, gồm ma trận truy vết, xung đột và các quyết định sản phẩm được phê duyệt.
- Đã có tài liệu kiến trúc backend và kế hoạch triển khai theo từng milestone. Các tài liệu này mô tả định hướng và tiêu chí; sự tồn tại của tài liệu không chứng minh mã nguồn đã đáp ứng.

### Backend đang hoạt động ở mức M0

- Backend Go hiện hành nằm ở [`backend/`](../backend/). Backend Gin/GORM/password/JWT cũ được giữ trong [`backend/legacy/`](../backend/legacy/) dưới dạng module riêng, ngoài build hiện hành. Có bản lưu trước chuyển đổi ở `scratch/rendez-backend-before-m0-20260923.tar.gz` (thư mục `scratch/` bị Git bỏ qua).
- [`backend/cmd/api/main.go`](../backend/cmd/api/main.go) tạo HTTP server bằng `net/http` và chi; dùng `pgxpool` kết nối PostgreSQL, `slog` ghi log, timeout HTTP và xử lý tín hiệu dừng sạch.
- [`backend/migrations/core/00001_bootstrap.sql`](../backend/migrations/core/00001_bootstrap.sql) là migration Goose ban đầu. Cơ sở dữ liệu M0 chỉ có metadata Goose, chưa có bảng nghiệp vụ.
- `GET /health/live` trả `200` khi API chạy, không cần truy vấn database. `GET /health/ready` kiểm tra kết nối và phiên bản migration, trả `503` nếu chưa sẵn sàng.
- [`backend/docker-compose.yml`](../backend/docker-compose.yml) khai báo PostgreSQL `18.4`, cổng host `127.0.0.1:55432`, database `rendez_core`, volume riêng của Compose project `rendez-core`. [`backend/Makefile`](../backend/Makefile) và [`backend/README.md`](../backend/README.md) cung cấp lệnh chạy cục bộ. `.env.example` chỉ là mẫu; Makefile không tự nạp file `.env`.
- Module hiện hành dùng chi, pgx và Goose. Chưa có auth, bảng domain, API địa điểm, tìm kiếm, giá, yêu thích, đóng góp, OCR hay Admin.

### Kiểm chứng đã chạy

- `make -C backend local-db` và `make -C backend migrate`: PostgreSQL cục bộ khởi động, Goose áp dụng migration.
- `make -C backend verify-m0`: target **hiện được cài đặt** build và chạy unit/integration test thành công. Tên target chưa chứng minh nó đáp ứng toàn bộ hợp đồng `verify-m0` trong tài liệu.
- `cd backend && go mod verify && go vet ./... && go test -count=1 ./...`: đạt.
- `docker compose -f backend/docker-compose.yml config --quiet`: đạt.
- `TestM0Postgres` đã chạy với PostgreSQL thật: tạo database test trống, áp dụng Goose hai lần, kiểm tra không có bảng domain, kiểm tra readiness rồi xóa database test. Một lần kiểm thử riêng dùng image `postgres:18.4` đã có sẵn, trong container tạm với cổng loopback ngẫu nhiên; container này đã được xóa sau test. Không sử dụng `kotoba_db`.
- Đã chạy API và gọi HTTP thực tế: `/health/live` và `/health/ready` đều trả `200` khi database hoạt động. Trong một lần kiểm thử thủ công, dừng database khiến liveness vẫn `200`, readiness trả `503`; sau khi khởi động database, readiness trở lại `200`. SIGTERM dừng API sạch. Đây là kiểm tra thủ công; `verify-m0` hiện chưa tự động thực hiện toàn bộ các bước đó.

Trạng thái tiến trình và container tại một thời điểm không phải trạng thái bền vững của checkpoint. Kiểm tra lại bằng `docker ps` và `curl` trước khi dựa vào chúng.

## Đối chiếu với M0 trong kế hoạch

**Kết luận: M0 hoàn thành một phần, chưa đạt cổng nghiệm thu đầy đủ của [`backend-implementation-plan.md` mục 8](../docs/backend-implementation-plan.md#8-m0-detailed-implementation-plan--runnable-skeleton).** Các phần chạy được ở trên là bằng chứng hẹp, không phải bằng chứng hoàn tất milestone.

Những khác biệt hoặc thiếu sót đã xác định:

| Tiêu chí trong kế hoạch | Trạng thái hiện tại |
|---|---|
| `tools`, `local-up`, `generate` và hợp đồng `test-integration TEST_RUN=…` | Makefile chưa có các target/hợp đồng này. Hiện có `run` và `verify-m0` đơn giản hơn. |
| Goose/sqlc được pin và cấu hình generation | Goose là dependency Go; chưa có `sqlc.yaml`, tool setup được pin hay `make generate`. |
| Dockerfile cho API với phiên bản Go tương thích | Chưa có Dockerfile hiện hành; API đang chạy trực tiếp bằng Go trên host. |
| `APP_ENV` chỉ nhận development/test/production | Chưa có `APP_ENV` trong cấu hình hiện hành. |
| Lỗi HTTP 404/405 dạng JSON; request ID và log method/status/duration theo route | Chưa được triển khai. Hiện có log startup/migration/shutdown và JSON cho health. |
| Test config, lỗi an toàn, routing và signal shutdown | Chưa có bộ test tự động tương ứng. |
| `verify-m0` tự kiểm tra database test trống, database offline và shutdown | Integration test có database trống và closed-pool readiness. Kiểm tra database offline và shutdown đã làm thủ công nhưng chưa nằm trong target. |
| Test DB bằng Compose project/database riêng | Test hiện tạo database riêng trong PostgreSQL được cấp qua `TEST_DATABASE_URL`; target chưa dựng một Compose project test riêng. |

Không nên bắt đầu M1 hoặc tuyên bố M0 đạt tài liệu chỉ dựa trên hai health endpoint trả `200`. M1 theo kế hoạch là phiên đăng nhập phát triển User/Admin với opaque session; chưa được triển khai.
